# Enforced rules

Each rule the engine enforces by code and test, beside its enforcer. `AGENTS.md` points here; add a row when you add an enforced rule.

| Rule | Enforcer |
|---|---|
| Optional scheduler JSON reads go through `jqf_optional_file`; only a truly absent path is quiet, while an existing unreadable or malformed file still goes through `jqf`. | `engine/mac-autopilot/scheduler.d/core.sh`; `engine/mac-autopilot/intake-missing-state.test.sh` |
| `jqf` stays quiet only for the exact closed-consumer EPIPE (`writing output failed: Broken pipe`): a consumer that stops reading a jqf stream early (loop `break`/`return`, `head -n`) is not an error, while parse/runtime errors and other write failures (ENOSPC etc.) still log. | `engine/mac-autopilot/scheduler.d/core.sh`; `engine/mac-autopilot/jqf-epipe.test.sh` |
| A REQUEST-CHANGES whose `review-findings` block does not parse never reaches repair: the scheduler records `block=missing`, re-asks the same head once with the findings contract, and escalates to the supervisor if the re-ask fails too. | `engine/mac-autopilot/scheduler.d/harvest-workers.sh`; `engine/mac-autopilot/scheduler-gates.test.sh` |
| A `models.*` config key naming a model-policy-forbidden family is skipped at `pick()` (fixed key order, logged) and named in a config-load warning; it is never dispatched silently. | `engine/mac-autopilot/scheduler.d/models.sh`; `engine/mac-autopilot/scheduler-gates.test.sh` |
| Incident implement/repair reports are structurally checked before review, by the pre-review self-check (a failure turns it red, so the original session repairs the report through self-fix) and at harvest (one same-session read-only continuation); the review-time gate remains authoritative. All three call `incident_report_gate_reason`, and a negated mention such as "no escalation was needed" is not a stated escalation. | `engine/mac-autopilot/scheduler.d/review-rules.sh`; `engine/mac-autopilot/scheduler.d/self-check.sh`; `engine/mac-autopilot/scheduler.d/harvest-workers.sh`; `engine/mac-autopilot/incident-report-self-check.test.sh`; `engine/mac-autopilot/incident-prior-art-gate.test.sh`; `engine/mac-autopilot/incident-report-resume.test.sh` |
| Parent-relative defaults use the physical engine-version parent while `ZF_ENGINE_DIR` stays logical for live-link behavior. | `engine/config.sh`; `engine/config.test.sh` |
| Review and rereview must use a model family different from the unit/worker that wrote the head; Codex heads try GLM then policy-authorized Sonnet, GLM heads try Codex then Sonnet, and unavailable independent reviewers leave the stage pending with one bell alert. | `engine/lib.d/model-policy.sh`; `engine/mac-autopilot/scheduler.d/models.sh`; `engine/mac-autopilot/review-family.test.sh` |
| A repair with no findings and a confirmed unchanged-head `repair-no-push` spends no stop-loss or repair-cap round; requeueing an unchanged head with no actionable findings or a confirmed no-push repair sends it to rereview. | `engine/mac-autopilot/scheduler.d/stop-loss.sh`; `engine/mac-autopilot/scheduler.d/evals-arbiter.sh`; `engine/mac-autopilot/noop-repair-rounds.test.sh` |
| Triage routes already-delivered work to `awaiting-release` only through `conclude_merged_run` with a PR verified merged into main; `wontfix` remains for genuinely declined work. | `engine/run-triage.sh`; `engine/run-triage.test.sh` |
| Sonnet fallback commands retain `Read,Grep,Glob,Bash` and `dontAsk`, permit the configured test runners, and do not grant git push or GitHub write commands. | `engine/mac-autopilot/scheduler.sh`; `engine/mac-autopilot/scheduler.d/worker-command.sh`; `engine/mac-autopilot/worker-command.test.sh` |
| An ordinary change lands on main in one command with `bash tools/quick-land.sh --test "<cmd>" --prior-art "<URL or no external prior art: reason>" "<subject>"` (zenoforge_direct_live_2026_11_12): code needs `--prior-art` (written into the commit message as `## prior-art`) and at least one `--test`, run through `tools/test-receipt.sh` at the committed HEAD (a red test stops the landing, the branch stays); a Markdown-only change needs neither. It refuses `engine/vendor/`, gate files, rule-lane files, VectA override files, deleted test suites, a size-ratchet growth and any HEAD other than origin/main. | `tools/quick-land.sh`; `engine/quick-land.test.sh` |
| When `delivery.revert_rate_30d_pct` or `flow.main_red_hours` goes UNHEALTHY on a fresh `node-health.json`, the scheduler logs a `reliability breach` line and changes no limit; each metric clears only when back to OK, so WARN holds, and a missing, stale or unreadable scorecard logs nothing. | `engine/mac-autopilot/scheduler.d/health-release.sh`; `engine/mac-autopilot/reliability-cap.test.sh` |
| Engine PRs use `tools/merge-pr.sh`; pending checks are allowed except on gate files (override name `gate-ci`), while failed checks require their exact names in `ZF_MERGE_OVERRIDE`; a non-test PR needs a `## prior-art` section (override name `prior-art`). Every refusal names its corrective action (`fix:`) before any override name. | `tools/merge-pr.sh`; `engine/merge-pr-helper.test.sh` |
| A pipeline unit never changes the protected paths in `engine/state/rule-files.json` (gates, review rules, evaluators, pin, watchdog, rollback, credentials, and the rule lane itself; a key ending in `/` covers a directory, and a vendored `ZF_PACK_REL` copy counts too). The refusal is `rule-lane: decision=unit-reject` at merge admission and the unit goes to the supervisor, whose changes get a syntax check only. | `engine/rule-lane.sh`; `engine/state/rule-files.json`; `engine/rule-lane.test.sh` |
| Issue-pipeline advisor units receive the configured provider job directory through `systemd-run` environment forwarding. | `engine/issue-pipeline.sh`; `engine/issue-pipeline.test.sh` |
| Automatic issue creation applies `auto-filed`; the shared classifier also recognizes `incident`, `prod-anomaly`, `Incident: `, `factory-f`, and the configured production anomaly title prefix, excluding these tickets from founder requirements and sorting them after non-auto tickets within each intake priority. | `engine/lib.d/guarded-write.sh`; `engine/pipeline-issue-upsert.sh`; `engine/mac-autopilot/scheduler.d/core.sh`; `engine/mac-autopilot/founder_reqs.py`; `engine/mac-autopilot/scheduler.d/intake.sh`; `engine/mac-autopilot/founder_reqs.test.sh`; `engine/mac-autopilot/intake-auto-filed.test.sh`; `engine/mac-autopilot/scheduler-auto-filed.test.sh`; `engine/pipeline-issue-upsert.test.sh`; `engine/roadmap-issue-create.test.sh` |
| Intake priority applies the configured founder floor and non-fruit cap after scoring, ranks hotfix/incident above bugs and fruit enhancements above off-market work, records the overlay reason on its decision event, and dispatches ready units in that tier order before stage/lane order. | `engine/mac-autopilot/config.template.json`; `engine/intake-priority.sh`; `engine/intake-backlog.sh`; `engine/ts-judge.mjs`; `engine/mac-autopilot/scheduler.d/stop-loss.sh`; `engine/intake-priority-overlay.test.sh` |
| When `origin/main` moves, the CI admission station runs `git merge-tree` on each open factory PR in an idle stage and sends a text conflict to repair through `merge_conflict_to_repair`; a head goes to repair once, a unit already `repair-pending` from a conflict with no `write-start` since is not flagged again by any path, the `merge-conflict-attribution` line names the real conflicting paths, units at the repair cap, session-owned PRs, `hand/` branches and supervisor-owned units are skipped, and the sweep proves no semantics. | `engine/mac-autopilot/scheduler.d/merge-tree-sweep.sh`; `engine/mac-autopilot/scheduler.d/merge-lane.sh`; `engine/mac-autopilot/scheduler.d/merge-tree-sweep.test.sh` |
| A unit's repeat merge conflict whose conflicting paths are all hot shared files (the journal under the target's `release.json` `migration.path`, the one directory the pack renumber hook owns, so a root `migrations/` journal is not resolved; `lessons/CATALOG.md`, `CONFLICT_UNION_RE`) is resolved by `conflict_auto_resolve`: a merge of main with the journal rebuilt as main plus the PR's new entries (then the pack renumber hook) or the catalog union-merged, pushed with a lease on the observed head, history `conflict-auto-resolved`, approval cleared, no repair dispatch; a first conflict, any other path, a missing hook, a failed step or three earlier resolutions go to repair as before. | `engine/mac-autopilot/scheduler.d/conflict-resolve.sh`; `engine/mac-autopilot/scheduler.d/merge-lane.sh`; `engine/mac-autopilot/scheduler.d/conflict-resolve.test.sh` |
| A source file over 800 lines may shrink but not grow, and a new or newly oversized file must stay at or under 800: sizes are baselined in `tools/size-baseline.txt`, and raising a line there is the visible, deliberate exception. | `tools/size-ratchet.sh`; `engine/size-ratchet.test.sh` |
| Evals never gate a merge, but an eval regression on a delivered change (prompts, `AGENTS.md`, `engine/vendor/`) opens one revert PR through `open_deploy_revert_pr` kind `eval`, merged by `engine/sweep-merges.sh` once its checks are green; a change already reverted is never reverted again. | `engine/mac-autopilot/scheduler.d/evals-arbiter.sh`; `engine/deploy-culprit.sh`; `engine/sweep-merges.sh`; `engine/mac-autopilot/eval-regression-revert.test.sh` |
| A dispatched worker's write below the deployment checkout root is refused loudly from node and python (the `engine/worker-write-guard` preloads, set by `worker_write_guard_env`), with the supervisor scratch kept writable; the incident-rule lesson entry belongs to the unit's own checkout registry, and a reviewed diff without its lesson row is NOT_READY. | `engine/worker-write-guard/`; `engine/mac-autopilot/scheduler.d/worker-scope.sh`; `engine/mac-autopilot/scheduler.d/dispatch.sh`; `engine/incident-rule.sh`; `engine/worker-write-guard.test.sh` |
| A worker started through `bin/luna` or `bin/zc` cannot run `pnpm`, `npm` or `corepack` install-type commands while a `node_modules` in its work tree (root, `*/`, `*/*/`) is a symlink or resolves outside it: the `engine/bin/install-guard` PATH shim exits 1 and names the fix. A symlinked `node_modules` plus install rewrote the shared checkout's modules dir on 2026-11-05. | `engine/bin/install-guard/guard`; `engine/bin/install-guard.test.sh` |
| A unit may spend at most `supervisor_arbiter.unit_cap` (default 4) arbiter dispatches over its whole life, counted from `supervisor-arbiter` history ignoring round markers; at the cap (or the 24 h ceiling) the scheduler itself applies the default decision in the same tick — obsolete closes the unit, one recut route when the unit has no PR, otherwise park — records `supervisor-cap-default`, and never goes to the founder or waits on a person. The default never closes an issue or a PR, and an on-hold issue gets no default until its hold ends. | `engine/mac-autopilot/scheduler.d/units.sh`; `engine/mac-autopilot/scheduler.d/supervisor-arbiter.sh`; `engine/mac-autopilot/supervisor-arbiter.test.sh` |
| The same unit with the same normalised escalation reason (digits and SHAs removed) is not arbitrated a second time while no delivery, approval, ready-to-merge, merge or new PR head has come since its last arbiter run: the scheduler applies the spent-budget route in the same tick (one recut when the unit has no PR, otherwise park), spends no model run, and appends no stage; the route's own history event starts with `supervisor repeat guard:` and `supervisor.repeat_guard_24h` counts it. | `engine/mac-autopilot/scheduler.d/units.sh` (`supervisor_repeat_arbitration`, `supervisor_cap_default` trigger `repeat`); `engine/mac-autopilot/scheduler.d/supervisor-arbiter.sh`; `engine/mac-autopilot/arbiter_health.py`; `engine/mac-autopilot/supervisor-arbiter.test.sh`; `engine/mac-autopilot/node_health.test.sh` |
| A unit whose lifetime fresh tokens (`spend_runs`, the same `unit_spend` computation the dashboard uses) pass `token_park_soft_tokens` (1,200,000) parks once for one arbiter decision with the per-run spend table and a class, which refills it once; at `token_park_hard_tokens` (2,400,000) it parks for good, no ruling kind refills it, and the supervisor inbox hears of it once. | `engine/mac-autopilot/scheduler.d/stop-loss.sh`; `engine/mac-autopilot/spend_ledger.py`; `engine/mac-autopilot/token-spend-gate.test.sh` |
| Triage routes a `ready-for-human`/`needs-owner` verdict or an unconfirmed phase-3 L2 freshness block to the advisor only when `advisor_reason` is `irreversible`, `production-data` or `security`; missing or unrecognized values default to `none`, autonomy admission remains enforced, and each default logs its source. A pending advisor convergence pass advances a leftover `model_policy.step == advisor` to its `on_success` step once and logs the policy-step decision as `kept`, so the same episode is not routed on every tick. | `engine/run-triage.sh`; `engine/lib.d/triage-default.sh`; `engine/run-triage.test.sh`; `engine/run-triage-batch.sh`; `engine/lib.d/route-advisor.sh`; `engine/run-triage-batch.test.sh` |
| A line hold (`release_train.enabled=false` in the runtime config, or a PAUSE the pipelines honour) is only held on purpose with an owner and an unexpired `expires_at` (config `release_train.hold`, PAUSE JSON `owner`/`expires_at`; plain text counts as no owner): a hold with no owner, no expiry or a past expiry counts in `holds.line_violations` and appends one alerts/events.md line plus one supervisor inbox line per hold per day; expiry never re-enables the held line. | `engine/mac-autopilot/line_holds.py`; `engine/mac-autopilot/node_health.py` (`--inbox`); `engine/mac-autopilot/node_health.test.sh`; `engine/lib.test.sh` (PAUSE validity unchanged) |
| Verified post-deploy evidence writes `$AGENT_HOME/state/live-sha.json`; delivery counts first-parent `origin/main` product commits using the merge lane's `NONPRODUCT_PATHS_RE` (missing SHA is unhealthy NO-DATA; oldest age is healthy ≤24 h and unhealthy ≥72 h), and founder 上线 requires `released` plus a merge/land SHA ancestral to live SHA. | `engine/lib.d/release-close.sh`; `engine/mac-autopilot/live_delivery.py`; `engine/mac-autopilot/founder_reqs.py`; `engine/mac-autopilot/live_delivery.test.sh`; `engine/mac-autopilot/founder_reqs.test.sh`; `engine/lib-conclude.test.sh` |
| A blocking review finding class seen in a second unit opens one deterministic-check issue through pipeline-issue-upsert; later units comment on it. | `engine/mac-autopilot/review-contract.sh`; `engine/mac-autopilot/scheduler.d/reports.sh`; `engine/mac-autopilot/review-contract.test.sh` |
| A review prompt carries the verification result for the head it reviews: command, exit code and bounded evidence when passed; RED or SKIPPED stated explicitly. | `engine/mac-autopilot/scheduler.d/review-rules.sh`; `engine/mac-autopilot/scheduler.d/self-check.sh`; `engine/mac-autopilot/verification-self-check.test.sh` |
| A test file may not add lines that extract a function from a source file by text range (`sed -n '/^name() {/,/^}/p'`); the per-file count may only go down. | `engine/source-extract-ratchet.test.sh`; `engine/source-extract-baseline.txt` |
