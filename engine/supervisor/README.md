# Session supervisor

Hooks inject configured context and guard commands and replies. The launcher starts a session with a role; the watchers report operational state. Install links after preparing a JSON configuration and confirming its targets exist:

```
bash engine/supervisor/install.sh --config /path/to/config.json
bash engine/supervisor/install.sh --apply --config /path/to/config.json
```

The default is a dry run. An existing regular file whose content differs from its target is refused: install prints both paths, changes nothing and exits non-zero, in a dry run too. An identical regular file is backed up under the home directory, then linked. Settings are not edited. Set `ZF_SUPERVISOR_CONFIG` to override the installed configuration link. Paths beginning with `~/` expand against `HOME`.

Configuration keys: `role_env`, `sources` (policy, quota files, role_dir), `state_dir`, `seen_state_template`, `coach` (enabled, role, report_dir, marker_file, stale_days, new and stale messages), `labels`, `claim_path`, `demo_gate`, `demo_gate_env`, `ledger_script`, `ledger_env`, `ledger_label`, `command_patterns`, `push_pattern`, `command_messages`, `readiness_pattern`, `claim_message`, `ruling_trigger`, `ruling_carrier`, `ignored_user_prefixes`, `ruling_message`, `launcher` (cwd, roles, role_dir, prefix), `watch` (paths, filters, units, thresholds, endpoint, scope and issue settings), `rulings_clone`, and `links` (objects with link and target). `supervisors` declares roles as `{name: {state, scope, reports_to, ruling?, state_changed_at?}}`. Defaults for `head`, `hotfix`, `zenoforge` and `coach` live in `supervisors.default.json`; a target config overrides any field per role and may add roles. `state` is `active` or `closed`; anything else fails. `vrole <role>` refuses a role that is not `active` (exit 3), naming its state and `ruling`. A role with no entry launches as before. `vrole --list` prints one tab-separated line per role (name, state, reports_to, ruling, scope) from config only; it does not inspect processes or sessions. Instance data (real rulings, state changes, extra roles) belongs in the target's private config, not in this repo.

Regular expressions use JavaScript syntax except the watcher filters and scope glob, which use their respective shell tools' syntax. Message templates use the placeholders shown in the configuration.

Run `bash engine/supervisor/tests/run.sh` for isolated checks. `parity.sh` compares hook exit status and output against an older hook directory, using fixture files named `<name>.hook`, `<name>.stdin`, an optional shell environment file `<name>.env` (or `<name>.vars`), and optional `<name>.home/` directory. `@HOME@` in stdin is replaced with the fixture home path.

`watch/memory-check.py` keeps agent memory notes correct while the factory runs: every 6 hours (`systemd/zenoforge-memory-check.timer`, Nice 19, low CPUWeight) it backs up the memory dirs, copies the 10 least recently checked notes, has one worker verify them against `origin/main` and recent transcripts, and applies the result as the only writer, skipping any note a peer session changed meanwhile. It only corrects false tokens: it refuses to delete a note with a Why or How to apply block or a founder quote, and refuses a rewrite that touches the name, description, Why or How to apply block, changes more than 3 lines, or changes a line to something dissimilar; refused rewrites are written to `proposals/YYYY-MM-DD.md` for a human. Logs and `checked.json` live in `~/.zenoforge/state/memory-check/`. The timer is not in `pipeline-timers.list`; enable it by hand. Run `bash engine/supervisor/watch/memory-check.test.sh` for isolated checks.
